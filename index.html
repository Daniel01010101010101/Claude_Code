Bloque 1 · Fundamentos · 10 min

Qué es Claude Code y por qué cambia cómo programas

Claude Code es un agente de programación. Un chat normal te responde con texto y tú copias y pegas. Un agente trabaja dentro de tu proyecto: lee tus archivos, ejecuta comandos, edita código, lanza los tests, mira si fallan, corrige y sube los cambios a GitHub. Tú describes qué quieres; Claude explora, planifica y lo implementa mientras tú supervisas.

En esta clase lo usaremos desde la app de Claude o desde el navegador, sin instalar nada: Claude trabaja en un entorno en la nube, un ordenador virtual con tu repositorio de GitHub ya descargado.

Chat de IAAutocompletado en el editorClaude Code (agente)
Ve tu proyectoSolo lo que pegasEl archivo abiertoTodo el repositorio de GitHub
Ejecuta códigoNoNoSí: tests, scripts, instalaciones
Comprueba su trabajoNoNoSí, repite hasta que pasan los tests
Cambios en varios archivosManualLínea a líneaCoordinados, con plan previo
GitHubNoNoRamas, commits y pull requests

Ventajas para ti como estudiante

Aprendes explicando

Le pides que te explique un archivo, un error o una decisión. Con el estilo Learning te deja huecos TODO(human) para que escribas tú las partes importantes.

Sin instalar nada

Todo ocurre en un entorno en la nube con Python, Node y git ya preparados. Funciona igual en el portátil de clase, en casa o desde el móvil.

Buenas prácticas gratis

Tests, commits con sentido, README, separación train/test… Si se lo pides, lo hace siempre, y tú ves cómo se hace bien.

Habilidad profesional

Dirigir agentes (contexto, especificación, verificación) es lo que se pide ya en los equipos de software y datos.

Dónde puedes usarlo

Navegador

claude.ai/code: entra con tu cuenta de Claude y empieza. Es la forma más rápida.

App de escritorio

App de Claude para Windows, macOS y Linux, pestaña Code. Elige Cloud para trabajar en un entorno en la nube.

Móvil

Pestaña Code de la app de Claude: revisa cómo va una tarea o lanza otra desde el teléfono.

Claude Code también existe como programa de terminal y como extensión para editores. Esta clase no los necesita: todo se hace desde la app o el navegador.

Bloque 1 · Fundamentos · 10 min

Tu primera sesión, sin instalar nada

Necesitas una cuenta de GitHub y un plan de Claude con Claude Code: Pro, Max, Team o Enterprise. El plan gratuito no incluye Claude Code.

  1. Abre Claude Code

    Entra en claude.ai/code e inicia sesión con tu cuenta de Claude. Si prefieres la app de escritorio, abre la pestaña Code.

  2. Conecta tu cuenta de GitHub (solo la primera vez)

  3. El entorno Default se crea solo

    En los planes Pro y Max, al conectar GitHub se crea un entorno llamado Default, con acceso a red Trusted: puede instalar paquetes de PyPI o npm y hablar con GitHub, y nada más. En Team y Enterprise aparece un formulario: deja los valores que trae y pulsa Create & finish. Para empezar no tienes que tocar nada; en el bloque 3 verás cómo personalizarlo.

  4. Elige repositorio, rama y modo, y escribe la tarea

  5. Mira cómo trabaja y revisa el resultado

    Claude descarga el repositorio en una máquina virtual nueva, trabaja y, al terminar, sube una rama claude/… a GitHub. Tú revisas los cambios y decides si crear un pull request. Puedes cerrar la pestaña: la sesión sigue en la nube y la retomas desde cualquier dispositivo.

Prueba rápida para la claseQue cada estudiante abra una sesión sobre cualquier repositorio público suyo (o uno nuevo con solo un README) y escriba: ¿Qué versión de Python hay en este entorno y qué paquetes de ciencia de datos faltan para usar scikit-learn? Claude ejecutará comandos en el entorno y responderá con datos reales.

Bloque 2 · Interfaz y modelos · 10 min

La interfaz de Claude Code, parte por parte

Así se ve una sesión en la nube en la app de escritorio. En claude.ai/code la distribución es casi la misma.

  1. Barra lateral. Nuevo abre una sesión (Ctrl+N), Buscar encuentra conversaciones antiguas, Artefactos guarda las páginas que Claude publica y Personalización gestiona tus skills y conectores.
  2. Sesiones agrupadas por repositorio. Cada tarea es una sesión con su propia rama. El ＋ junto al repositorio abre otra sesión sobre él.
  3. Título de la sesión. Haz clic para renombrarla. El ⌄ abre el menú de la sesión, desde donde puedes, por ejemplo, editar su entorno.
  4. Conversación. Tus mensajes, lo que Claude hace y las tarjetas con los archivos cambiados. Pulsa una tarjeta para ver el detalle.
  5. Cuadro de mensaje. El ＋ adjunta archivos e imágenes (capturas de errores, diseños), muestra los comandos y activa conectores. El micrófono sirve para dictar.
  6. Modo de permisos. En la nube puedes elegir Auto, Aceptar ediciones o Plan. Lo explicamos en el bloque 4.
  7. Modelo y nivel de esfuerzo. Qué modelo trabaja y cuánto piensa antes de actuar. El anillo de al lado muestra cuánto contexto y cuánto uso de tu plan llevas. Lo vemos en la sección siguiente.
  8. Entorno. En qué entorno corre la sesión, qué repositorio tiene descargado y en qué rama está trabajando Claude.
  9. Contexto. Cuánto de la memoria de trabajo de esta conversación está ocupado. Si se llena mucho, abre una sesión nueva para la siguiente tarea.
  10. Resultados. Los artefactos y archivos que ha creado o modificado en esta sesión.
  11. Cambios. Líneas añadidas y quitadas respecto a la rama de partida. Ábrelo para ver el diff y comentar líneas concretas; Crear PR abre un pull request en GitHub.
Atajos útiles en la appEsc para a Claude · Ctrl+N nueva sesión · Ctrl+/ lista de atajos · Ctrl+Shift+M modo · Ctrl+Shift+I modelo · Ctrl+Shift+E esfuerzo · Ctrl+; pregunta aparte sin ensuciar la conversación. En Mac, Cmd en lugar de Ctrl.

Bloque 2 · Interfaz y modelos · 10 min

Los modelos: cuál usar en cada momento

El modelo es el "cerebro" que trabaja en la sesión. Lo cambias en el selector junto al botón de enviar. Todos los de la familia Claude 5 tienen una ventana de contexto de 1 millón de tokens.

Más rápido y ligeroMás capaz
Rápido

Haiku 5.5

Rápido y eficiente para tareas sencillas: preguntas cortas, renombrar, explicar un error, pequeños cambios.

En clase: dudas rápidas sin gastar mucho uso del plan.

Día a día

Sonnet 5.5

Pensado para el trabajo diario de programación: equilibrio entre velocidad y calidad.

En clase: la web, los tests, el README.

Predeterminado

Opus 5.5

Para razonamiento complejo. Es el modelo que se usa por defecto en los planes Pro, Max, Team y Enterprise.

En clase: planificar el proyecto y el entrenamiento del modelo.

El más potente

Fable 5.1

Para las tareas más difíciles y largas. Nunca viene seleccionado por defecto: hay que elegirlo, si tu plan lo incluye.

En clase: retos grandes, cuando los demás se atascan.

El nivel de esfuerzo

Junto al nombre del modelo aparece el esfuerzo (en la captura de la interfaz, Extra): cuánto piensa Claude antes de responder. A más esfuerzo, mejores resultados en problemas difíciles, pero tarda más y consume más uso del plan. Los niveles, de menos a más, son low, medium, high, xhigh y max (la app los muestra con nombres en español). Opus, Sonnet y Haiku 5.5 empiezan en medium.

SituaciónModeloEsfuerzo
"¿Qué hace esta función?"Haiku o SonnetBajo o medio
Crear la web con el lienzo y las barrasSonnetMedio
Planificar el proyecto o encontrar por qué baja la precisiónOpusAlto
Un fallo raro que ningún intento resuelveOpus o FableMuy alto o máximo
Cómo cambiarloCon el selector junto al botón de enviar, con los atajos Ctrl+Shift+I (modelo) y Ctrl+Shift+E (esfuerzo), o escribiendo /model sonnet y /effort high en el cuadro de mensaje. Todo lo que hace Claude cuenta para los límites de uso de tu plan: el anillo junto al modelo te muestra cuánto llevas.

Bloque 3 · Entorno y GitHub · 25 min

Conectar Claude a GitHub con un entorno en la nube

Un entorno es la configuración guardada del ordenador virtual donde trabaja Claude: qué red puede usar, qué variables tiene y qué se instala al arrancar. Cada sesión recibe una máquina nueva con tu repositorio descargado.

Qué trae el entorno sin configurar nada

Sistema

Una máquina virtual Ubuntu 24.04 nueva en cada sesión, con tu repositorio ya descargado.

Python

Python 3 con pip, uv, poetry, pytest, ruff, black y mypy. scikit-learn se instala con pip en segundos.

Más herramientas

Node.js 20–22, Java, Go, Rust, Docker, PostgreSQL, Redis, git y la CLI de GitHub.

Crear o editar un entorno

  1. Abre el selector de entorno

    En la pantalla de nueva sesión, pulsa el primer control debajo del cuadro de mensaje (el de ☁ Default). Para crear uno, elige New environment. Para editar uno, pasa el ratón por encima y pulsa el icono de ajustes que aparece a la derecha. En una sesión ya empezada: ⌄ junto al título → Edit cloud environment.

  2. Rellena el formulario

Acceso a redQué permiteCuándo usarlo
NoneSin salida a internet (salvo la propia comunicación con Claude)Código sensible que no necesita descargar nada
TrustedSolo dominios de confianza: PyPI, npm, GitHub y servicios en la nube habitualesCasi siempre. Es el que usa Default y el que recomendamos en clase
FullCualquier dominioSolo si la tarea necesita descargar de sitios fuera de la lista
CustomTu propia lista de dominios (puede incluir la de Trusted)Cuando necesitas uno o dos dominios concretos más

Script de configuración

Un script de Bash que prepara la máquina antes de que Claude empiece: instalar librerías o herramientas que no vienen de serie. Debe tardar menos de unos 5 minutos; entonces el entorno se guarda en caché y las siguientes sesiones arrancan ya preparadas (la caché dura unos 7 días o hasta que cambies el script).

Variables de entorno

Una por línea, en formato CLAVE=valor. No pongas contraseñas ni claves de API: cualquiera que use el entorno puede leerlas. Para claves, el entorno tiene un apartado de secretos de red que Claude usa sin verlos.

De la rama al pull request

  1. Claude sube una rama

    Al terminar, Claude sube sus cambios a una rama claude/… de tu repositorio. Tu rama main no se toca.

  2. Revisa los cambios

  3. Crea el pull request y fusiónalo

    Crear PR lo abre en GitHub (completo o como borrador). Allí lo revisas por última vez y pulsas Merge pull request. La sesión sigue viva: si GitHub Actions falla o alguien comenta, pega el error y pide que lo arregle, o activa Auto-fix en la barra de CI para que lo haga solo.

Una sesión por tareaCada sesión trabaja en su propia rama, así que puedes lanzar varias a la vez (por ejemplo, tres experimentos con distintos tamaños de red) sin que se pisen.

Bloque 4 · Prompts y control · 15 min

Cómo escribir prompts que funcionan

Claude puede deducir mucho, pero no leer tu mente. Cuanto más preciso el encargo, menos correcciones. Y lo más importante: dale una forma de comprobar su trabajo.

Las cinco piezas de un buen prompt

1 · Contexto

Qué es el proyecto y qué archivos importan. Nómbralos con su ruta: train.py.

2 · Objetivo

Qué quieres conseguir, concreto y medible. Un objetivo por prompt.

3 · Restricciones

Librerías permitidas, qué no tocar, estilo, límites de tamaño.

4 · Verificación

Cómo sabrá que ha terminado: tests, un comando, una captura, una métrica.

5 · Entrega

Qué quieres al final: commit, tabla de resultados, PR, resumen.

Antes y después

Vago

haz un modelo para los dígitos

No dice datos, modelo, métrica ni cómo comprobarlo.
Preciso

En train.py entrena un MLP de scikit-learn con load_digits. Separa train/test 80/20 con stratify y semilla 42 antes de aumentar datos. Imprime precisión y matriz de confusión. Ejecuta python -m pytest -q y no termines hasta que pase.

Contexto, objetivo, restricciones y verificación.
Vago

la web no funciona, arréglala

Claude tiene que adivinar qué falla.
Preciso

Al abrir index.html desde GitHub Pages sale este error en consola: [pega el error o la captura]. Encuentra la causa en index.html, arréglala sin silenciar el error y explícame por qué pasaba.

Síntoma, ubicación probable y qué significa "arreglado".
Vago

mejora el diseño

"Mejor" no se puede comprobar.
Preciso

[pega una captura del diseño que te gusta] Adapta index.html a este estilo: lienzo a la izquierda, barras de probabilidad a la derecha, que se vea bien en un móvil de 400 px. Haz una captura del resultado, compárala con la original y corrige las diferencias.

Referencia visual y comprobación visual.
Vago

añade tests

¿De qué? ¿Qué casos?
Preciso

Escribe un test en tests/test_model.py que recalcule la precisión desde model.json con la misma semilla que train.py y falle si baja de 0.93. Sin mocks. Ejecútalo.

Archivo, caso concreto, umbral y preferencia de estilo.

Técnicas avanzadas de prompting

      

        
Que Claude te entreviste
Para proyectos grandes: Quiero construir [idea]. Entrevístame en detalle con la herramienta AskUserQuestion sobre implementación, interfaz, casos límite y compromisos. Al terminar, escribe la especificación en SPEC.md. Luego abre una sesión nueva que implemente la especificación.

        
Investigar con subagentes
Usa subagentes para investigar qué opciones hay para ejecutar un modelo de scikit-learn en el navegador y compáralas. La investigación ocurre en otro contexto y tu conversación queda limpia.

        
Escritor y revisor
Una sesión implementa; otra, con contexto limpio, revisa: Revisa train.py buscando fugas de datos y errores en la métrica. Una mirada fresca no está sesgada por el código que acaba de escribir.

        
Pide pruebas, no promesas
Enséñame la salida de los tests, enséñame la matriz de confusión, muéstrame el comando que ejecutaste. Revisar evidencias es más rápido que repetirlo tú.

        
Contenido rico
Adjunta capturas de errores o diseños con el ＋ (o arrástralas), pega mensajes de error completos y pasa enlaces a documentación: lee https://scikit-learn.org/… y aplica esa idea.

        
Corrige pronto y limpia
Esc en cuanto se desvíe. Si le has corregido dos veces lo mismo, el contexto está contaminado: abre una sesión nueva con un prompt mejor que incluya lo aprendido.

      

    


    
    

      

        
Bloque 5 · Memoria y skills · 10 min

        
CLAUDE.md: la memoria de tu proyecto

        
Cada sesión empieza de cero. CLAUDE.md es un archivo Markdown que Claude lee siempre al empezar: comandos, reglas y decisiones que no puede deducir del código.

      

      

        

          
ArchivoPara qué

          
            
CLAUDE.md en la raíz del repositorioInstrucciones del proyecto para todas las sesiones y para todo el equipo

            
CLAUDE.md dentro de una carpetaInstrucciones que solo aplican cuando Claude trabaja en esa carpeta

            
.claude/rules/*.mdReglas por temas (tests, estilo…), que pueden aplicarse solo a ciertas rutas

          
        

      

      

        
CLAUDE.md del proyecto de ejemplo
# Reconocedor de dígitos

Demo de ML que se publica en GitHub Pages.

## Comandos
- Instalar: `pip install -r requirements.txt`
- Entrenar: `python train.py` (escribe model.json)
- Tests: `python -m pytest -q`

## Reglas
- index.html es estático: sin frameworks ni servidor.
- predict() en JS = forward() de los tests.
- model.json < 1 MB.
- Nunca evalúes con datos de entrenamiento.
- Semillas fijas para reproducibilidad.

## Flujo
1. Cambios grandes: modo plan y espera aprobación.
2. Tras tocar el entrenamiento: train + tests.

    • 
            
  • Pregúntate por cada línea: ¿si la borro, Claude cometería errores? Si no, bórrala. Un CLAUDE.md largo hace que se ignoren las reglas importantes.
    • 
            
  • Puedes importar otros archivos con @docs/arquitectura.md.
    • 
            
  • Para empezar rápido, escribe /init: Claude analiza el repositorio y propone un CLAUDE.md. Después edítalo tú.

Bloque 5 · Memoria y skills · 15 min

        
Skills: enseña a Claude tus propios procedimientos

        
Una skill es una carpeta con un archivo SKILL.md: instrucciones, y opcionalmente scripts y documentos de apoyo, que Claude carga solo cuando hacen falta. Puede activarse sola cuando la tarea encaja o la llamas tú con /nombre-de-la-skill.

      

      
Por qué no gastan contexto: carga progresiva

      

        
Siempre cargado: name y description de cada skill
pocas decenas de tokens

        
Al usarse: el cuerpo de SKILL.md con las instrucciones
recomendado < 500 líneas

        
Si hace falta: reference.md, scripts/, plantillas…
solo lo que necesite

      

      
Por eso la descripción es lo más importante: debe decir qué hace la skill y cuándo usarla, porque es lo único que Claude ve para decidir.


      
Las dos formas de tener skills en la nube

      

        
En el repositorio
.claude/skills/<nombre>/SKILL.md
Viaja con el proyecto: la tiene cualquier sesión sobre ese repositorio y cualquier compañero que lo use. Es la que usaremos en el proyecto.

        
En tu cuenta
Barra lateral → Personalización
Skills activadas en tu cuenta de Claude. Se cargan solas en todas tus sesiones en la nube, sea cual sea el repositorio. Allí puedes activar skills ya disponibles y subir las tuyas.

Bloque 6 · Avanzado · 15 min

        
Nivel avanzado: las piezas y cuándo usar cada una

        
CLAUDE.md dice qué saber, las skills dicen cómo hacer una tarea, los hooks garantizan lo que siempre debe pasar, los subagentes trabajan aparte y los conectores enlazan con servicios externos. Todo se guarda en el repositorio, así que funciona en la nube.

      

      

        

          Subagentes
          
Asistentes especializados con su propio contexto

          
Archivos en .claude/agents/. Útiles para investigar o revisar sin llenar tu conversación. Úsalos diciendo usa el subagente revisor-ml para revisar los cambios.

          
.claude/agents/revisor-ml.md
---
name: revisor-ml
description: Revisa código de ML buscando fugas de
  datos, métricas engañosas y diferencias entre
  Python y JavaScript.
tools: Read, Grep, Glob, Bash
---
Eres una científica de datos sénior. Revisa git diff:
1. ¿Algo aprende de los datos de test?
2. ¿La métrica se calcula con datos no vistos?
3. ¿Hay azar sin semilla fija?
Indica archivo, línea y cómo arreglarlo.

        

        

          Hooks
          
Acciones automáticas que siempre ocurren

          
Comandos que Claude Code ejecuta en momentos concretos: al empezar la sesión, después de editar un archivo… A diferencia de CLAUDE.md, no dependen de que Claude "se acuerde". Este instala las dependencias al empezar cada sesión, en la nube y en cualquier otro sitio:

          
.claude/settings.json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command",
            "command": "pip install -q -r requirements.txt" }
        ]
      }
    ]
  }
}

          
Puedes pedírselo así: escribe un hook que formatee los .py con ruff después de cada edición.

        

        

          Conectores
          
Servicios externos dentro de la sesión

          
En el ＋ del cuadro de mensaje → Conectores activas los que tengas en tu cuenta de Claude (por ejemplo Google Drive o Notion) y Claude puede usarlos en la tarea. Su tráfico pasa por los servidores de Anthropic, así que no hace falta abrir la red del entorno. Se gestionan en Personalización.

        

        

          Sesiones en paralelo
          
Varios experimentos a la vez

          
Cada sesión tiene su máquina y su rama. Abre tres sesiones sobre el mismo repositorio y pide en cada una una variante (32, 64 y 128 neuronas). Compara las tablas de resultados y quédate con el mejor PR.

        

        

          Auto-fix
          
Que arregle solo los fallos del PR

          
Cuando ya hay un pull request, aparece una barra de CI en la sesión. Activa Auto-fix y Claude vigila el PR: si GitHub Actions falla o alguien deja un comentario, investiga y sube el arreglo. Requiere la Claude GitHub App en el repositorio.

        

        

          Estilo Learning
          
Claude como profesor

          
Con el estilo Learning, Claude explica sus decisiones y te deja huecos TODO(human) para que escribas tú el código clave. Actívalo para todo el proyecto en .claude/settings.json:

          
{ "outputStyle": "Learning" }

          
Con Explanatory solo añade explicaciones, sin pedirte código.

        

        

          Calidad
          
Revisión antes del PR

          
/code-review revisa los cambios de la sesión con un subagente de contexto limpio y devuelve una lista de problemas que puedes pedir que arregle. Úsalo siempre antes de Crear PR.

        

        

          Rutinas
          
Tareas programadas

          
Una rutina lanza una sesión en la nube según un horario o un evento de GitHub. Por ejemplo: cada lunes, reentrenar y abrir un PR si la precisión mejora. Consulta la guía de rutinas.

Bloque 7 · Proyecto · 50 min

        
Tu modelo de machine learning, de cero a producción

        
Vas a construir el reconocedor de dígitos de arriba: se entrena en Python con scikit-learn, se exportan los pesos a JSON y la web hace la predicción en el navegador. Sin servidor, así que GitHub Pages lo publica gratis. Todo desde la app de Claude.

      

      

        
# Estructura final
reconocedor-digitos/
├── CLAUDE.md              memoria
├── SPEC.md                especificación
├── train.py               entrena y exporta
├── model.json             pesos, 35 KB
├── index.html             la web
├── requirements.txt
├── tests/test_model.py    verificación
├── .claude/
│   ├── settings.json      permisos y hooks
│   ├── agents/revisor-ml.md
│   └── skills/
│       ├── entrenar-modelo/
│       └── convenciones-ml/
└── .github/workflows/
    └── deploy-pages.yml   CI + Pages

        

          
Cómo funciona por dentro

          
    
            
  1. Datos: 1.797 imágenes de 8×8 píxeles de dígitos manuscritos (load_digits).
    2. 
            
  2. Modelo: red neuronal de 64 entradas, 64 neuronas ocultas (ReLU) y 10 salidas (softmax).
    3. 
            
  3. Exportar: los pesos se guardan en model.json.
    4. 
            
  4. Web: el dibujo se recorta, se escala a 32×32 y se reduce a 8×8 como los datos originales; después se multiplican las matrices en JavaScript.
    5.

Bloque 8 · Publicar · 10 min

        
Publicar en GitHub Pages

        
GitHub Pages sirve archivos estáticos gratis en https://TU-USUARIO.github.io/NOMBRE-REPO/. Con GitHub Free funciona en repositorios públicos; para repositorios privados necesitas un plan de pago (el GitHub Student Developer Pack incluye GitHub Pro).

      

      

        

          
          
        

        

          
Publica tal cual los archivos de una rama. Necesitas que index.html y model.json estén subidos.

          
    
            
  1. Abre Settings → Pages en tu repositorio
    
              
            
    2. 
            
  2. Espera uno o dos minutos y abre tu web
    
              
    Arriba en la misma página aparecerá Your site is live at https://tu-usuario.github.io/reconocedor-digitos/. Cada push a main la actualiza.
    
            
    3. 
          

        

        

          
Más profesional: en cada push, GitHub entrena el modelo, pasa los tests y solo publica si todo está bien. Así nunca sale a producción un modelo roto.

          
    
            
  1. Cambia la fuente a GitHub Actions
    
              
    Settings → Pages → Build and deployment → Source: GitHub Actions.
    
            
    2. 
            
  2. Añade el workflow
    
              
    .github/workflows/deploy-pages.yml
    name: Entrenar y publicar en GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: pip install -r requirements.txt
      - run: python train.py          # entrena
      - run: python -m pytest -q      # si falla, no se publica
      - run: mkdir _site && cp index.html model.json _site/
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: _site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
    
            
    3. 
            
  3. Haz push y mira la pestaña Actions
    
              
            
    4. 
          

        

      

      
Esta misma página es un ejemplo realSe publica con el Método B. Su workflow, .github/workflows/pages.yml, pasa los tests del modelo y comprueba que no haya enlaces rotos antes de publicar. Puedes ver cada publicación en la pestaña Actions del repositorio.

Para todo el curso

        
Seguridad y buenas prácticas

      

      

        
Claves fuera del código y de las variables
Nunca pongas contraseñas ni claves de API en el código ni en las variables del entorno: quien use el entorno puede leerlas. Para GitHub Actions usa los Secrets del repositorio.

        
Red en Trusted
Deja el acceso a red del entorno en Trusted. Pasa a Full o Custom solo si una tarea concreta lo necesita, y vuelve después.

        
Revisa antes del PR
Lee el plan, recorre Cambios y pide explicaciones de lo que no entiendas. Tú eres responsable del código que entregas.

        
Main está protegido por ti
Claude trabaja en ramas claude/…. Nada llega a main hasta que tú fusionas el pull request en GitHub.

        
Contenido externo, con cuidado
Webs, issues o archivos descargados pueden contener instrucciones maliciosas. Activa skills y conectores solo de fuentes de confianza.

        
Integridad académica
Pregunta a tu profesor qué uso está permitido. Una buena regla: si no sabes explicar una línea, no la entregues. Usa el estilo Learning para escribir tú las partes clave.

        
Cuida el contexto
Mira el indicador de Contexto. Una sesión nueva por tarea; /compact si una sesión larga se llena. Un contexto limpio da mejores respuestas.

        
Controla el uso
El anillo junto al modelo muestra cuánto llevas del plan. Usa Haiku o Sonnet para lo sencillo y reserva Opus o Fable con esfuerzo alto para lo difícil.
